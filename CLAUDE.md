## Project layout

- `src/` — front end (pnpm + Vite + React + TS + Tailwind v4 + shadcn/ui). `@/` aliases `src/`.
  - `src/features/<domain>/` — UI per domain (e.g. `terminal/`).
  - `src/lib/ipc/<domain>.ts` — the only place that calls `invoke`/`Channel`; typed wrappers over Tauri commands.
  - `src/i18n/locales/{en,zh}.json` — all UI copy. Keys must match exactly (enforced by `src/i18n/locales.test.ts`).
  - `src/components/ui/` — shadcn components (`pnpm dlx shadcn@latest add <name>`).
  - UI follows `DESIGN.md`. `src/App.tsx` fills the `AppShell` slots (sidebar, tabs, workspace, filePanel, status); the Host list lives in `HostsSidebar` (`features/hosts/HostsPanel.tsx`). A tab holds one or more panes split in one orientation (`features/workspace/tabs.ts`, a pure reducer); a new pane kind extends the `PaneKind` union plus a case in `PaneContent` (`TabPanels.tsx`), and stays mounted while hidden or when neighbours split/close. A remote Terminal pane reports its Connection status (`connecting`/`connected`/`disconnected`) up to the tab dot and status bar. Window-wide shortcuts are a table in `features/workspace/shortcuts.ts` (macOS uses Cmd; elsewhere Ctrl+Shift, never plain Ctrl+letter, which the shell owns; a binding marked `appOnly` matches only when focus is outside a Terminal). The ⌘K command palette is `features/palette/`: a feature offers an action while mounted with `usePaletteActions(useMemo(() => [{ id, title, keywords?, shortcut?, run }], deps))`; register only actions that work. Ranking is `rankPalette` (`palette-search.ts`); recently opened Hosts are the `recentHosts` section. Semantic token classes only (literal hex only in `src/theme/terminal-themes.ts`); icon-only controls are `IconButton` with a `label`.
  - Settings and UI prefs go only through `src/lib/storage.ts`, backed by the versioned settings file (core `settings`). A feature declares its section next to its code with `defineSection(key, defaults, parse)` (`parse` repairs any stored value) and uses `useSetting` / `getSetting` / `setSetting`; changes apply at once and save in the background. To show a setting on the Settings tab (`features/settings/`), add a component of `SettingRow`s to `settingsPageSections` in `features/settings/sections.tsx`; list only settings that work. Core code reads a section with `SettingsStore::section::<T>()` (`#[serde(default)]` struct). Renaming a section or field needs a migration step in `settings.rs`. Window size/position are kept by `tauri-plugin-window-state`.
  - Terminals: every xterm is an `XtermView` (`features/terminal/XtermView.tsx`), which owns font/colours, search (Cmd+F / Ctrl+Shift+F), links, copy on select, right-click paste and the multi-line paste confirmation; a backend wires in through its `attach(xterm)` callback. Terminal preferences are the `terminal` settings section (`terminalSetting` in `features/terminal/terminal-prefs.ts`, `TerminalPrefs` repaired by `normalizeTerminalPrefs`), read and changed with `useTerminalPrefs()` and edited on the Settings tab (`features/settings/terminal-section.tsx`). Colour schemes are in `src/theme/terminal-themes.ts` (`terminalSchemes`, `resolveTerminalTheme`); a Host may set its own (`Host.terminalScheme`, opaque to the core). Clipboard and opening URLs go through `src/lib/ipc/system.ts` (Tauri clipboard-manager / opener plugins).
  - File panel (`features/files/`): one per remote Terminal pane, kept in `fileBrowsers` (`fileBrowsers.ts`, by pane id; `find(paneId)` to drive one, e.g. follow the Terminal's `cd`). Each is a vanilla Zustand store from `createFileBrowserStore(api, hostId)` (fake `FilesApi` in tests): `connect()` / `disconnect()`, `navigate(path)` (absolute, `~`, `~/x`), `up`, `refresh`, `open(entry)`, and `selection` (entry names in `path`, changed by `select(name, "only" | "toggle" | "range", displayedNames)`) for file operations and transfers to act on. File operations are store actions on entry names in `path` (`createFolder`, `rename`, `countForDelete`, `remove`, `setPermissions`): each refreshes and resolves with the `CommandError` (or `null`) for its dialog (`FileOperationDialogs.tsx`, opened from the context menu, the New folder button, F2 and Delete / Cmd+Backspace), never touching the listing's `error`; `operationErrorText` (`fileErrors.ts`) words their failures. Sorting/hidden-file filtering is the view's (`shownEntries` in `fileList.ts`, prefs in the `files` settings section). `followConnection(store, status, shown)` opens SFTP only once its pane is `connected` and the dock is shown (`useFilePanelDock().collapsed`), and closes it while the Connection is down, so a reconnect reopens it on the new Connection at the same path. Rows are virtualized at a fixed height (`visibleRows`). `open(entry)` on a file (or a link to one) starts a remote edit: `edits` lists them per File panel (`RemoteEditItem`: `opening` → `editing` → `uploading`/`uploaded`/`uploadFailed`, or `openFailed`), with `retryEdit(path)` / `closeEdit(path)`, shown by `RemoteEdits` in the panel footer. Edits survive `disconnect()` (a Connection drop); `dispose()` (the pane closed, via `fileBrowsers.retain`) closes them. The panel follows its Terminal's `cd` through `terminalCwds` (`terminalCwds.ts`): `RemoteTerminalView`'s `onCwd`/`onTerminal` feed it (wired in `TabPanels`), it navigates the pane's store when the reported directory changes, and `sync(paneId)` (the header button) goes back there, typing `terminal_report_cwd` into shells that don't report by themselves.
- `src-tauri/` — Cargo workspace root and the Tauri app crate (`sshastra`, lib `sshastra_lib`): a thin IPC bridge.
  - `src-tauri/src/commands/<domain>.rs` — Tauri commands, registered in `src-tauri/src/lib.rs`. Errors map to `CommandError { kind, message }` in `src-tauri/src/error.rs`.
  - `src-tauri/crates/sshastra-core/` — all domain logic, no Tauri dependency (CI checks this). Tests in `crates/sshastra-core/tests/`.
- Streams (terminal output, later transfer progress / Connection state) go to the UI through a `tauri::ipc::Channel` passed as a command argument, never polled. Terminals use one channel each: raw bytes for output, JSON `{ connection }` when a remote Terminal's Connection drops / reconnects, JSON `{ cwd }` when its shell reports its directory, then a JSON `{ exitCode }` message last.
- Host list state lives in the Zustand `hostsStore` (`features/hosts/hostsStore.ts`, built by `createHostsStore(api)` so tests inject a fake API). Every change goes through the HostStore first and is shown once saved; tree commands (`host_move`, `group_move`, `group_delete`) return the whole `HostTree`. Pure tree logic (nesting, fuzzy search, drop → move) is in `features/hosts/hostTree.ts`.
- In-app drag and drop uses `@dnd-kit/core` (pointer events), not HTML5 drag and drop, which Tauri's native file drop (`dragDropEnabled`) intercepts on Windows.
- Credentials (`credentials`): the `CredentialVault` trait keeps passwords and key passphrases under "Host id + `CredentialKind`" (keychain service `sshastra`, account `<host id>:password` / `<host id>:key-passphrase`). `credentials::system_vault()` is the OS keychain via `keyring`, or `NoVault` (`can_save() == false`) where there is none, e.g. Linux without a Secret Service. `ConnectionManager::with_vault` makes auth try the saved secret before prompting, forget it when rejected, and save a typed one whose `Secret.save` is set once it proves right; vault failures never fail a connect. `PasswordPrompt`/`PassphrasePrompt.can_save` drives the "save" checkbox; `Prompter::password`/`passphrase` return `Option<Secret>`. Tests use `MemoryVault`, never the real keychain. No credential is ever written to sshastra's own files (`tests/credential_vault.rs` checks).
- Core modules: `credentials` (CredentialVault), `edit` (RemoteEditor), `forward` (Port forward rules and PortForwarder), `hosts` (HostStore: versioned JSON (v2 adds Groups; Hosts carry `group_id`; siblings ordered by list position; v3 adds `Host.forwards`), atomic writes, no secrets; a format change bumps the version with a step in `migrate`, which also reads export files), `settings` (SettingsStore: versioned JSON of opaque sections, migrations), `known_hosts` (OpenSSH `known_hosts`, shared with the `ssh` CLI), `ssh` (ConnectionManager / Connection / RemoteShell), `ssh_config` (SshConfigImporter, below), `files` (RemoteFs / SftpFs / FsRegistry), `terminal` (Terminal trait, LocalPty, TerminalRegistry, ShellIntegration).
- `~/.ssh/config` import (`ssh_config`): `parse(text, &ParseContext, includes)` is pure (no file access; `Include` patterns go through the `includes` resolver, `FsIncludes` / `parse_user_config` on disk) and returns `ConfigHost`s (Jump hosts by name; `ProxyJump` hops that aren't aliases become Hosts of their own, named as written) plus `ImportIssue { entry, dropped, problem }`. `HostStore::import_ssh_config` saves them in one write, skipping taken names (and linking Jump hosts to them), returning `ImportReport { imported, skipped, issues }`; command `hosts_import_ssh_config`, palette action `hosts.importSshConfig`, Host list header menu (shared with export / import, below), empty-state button. Remote/Dynamic forwards are reported as unsupported until `ForwardKind` has them (TODO(#18) in `ssh_config.rs`). New `ImportProblem` kinds need `hosts.import.problems.<kind>` copy.
- SSH: get a Connection with `ConnectionManager::connect(&host, prompter)`; it is shared per Host and lives while any holder keeps its `Arc` (a RemoteShell holds one); dropping the last one disconnects. Concurrent connects to the same Host (or the same Jump host) coalesce on a per-Host slot (the later ones wait and share the result; if the first fails they try themselves). Anything needing the user mid-connect (host key, password, later passphrase / keyboard-interactive) is a method on the `ssh::Prompter` trait; the app implements it in `src-tauri/src/prompts.rs` as a prompt `Channel` plus the `prompt_answer` command. Host key Mismatch/Revoked is never a prompt: it fails with a `ConnectError`.
- Dropped Connections: Connections send keepalives (the `connection` settings section, `keepaliveSeconds`, default 30, 0 = off; `ConnectionSettings` in core, `connectionSetting` in `features/connect/connection-settings.ts`), applied by `ConnectionManager::set_keepalive_interval` to Connections opened afterwards. A remote Terminal is an `ssh::RemoteTerminal`, opened with a `connect` closure it calls again to reconnect: when its Connection drops it sends `TerminalEvent::Connection(ConnectionState::Reconnecting { attempt, attempts })`, retries with doubling delays (`ReconnectPolicy`, 3 tries from 1 s; refusals such as auth failures or a cancelled prompt stop early), then `Connected` with a new shell in the same Terminal, or `Disconnected { reason }` and waits for `Terminal::reconnect` (`terminal_reconnect`). The UI covers the Terminal with `DisconnectedOverlay` meanwhile. `Connection::open_shell` alone does not reconnect.
- ShellIntegration (`terminal::shell_integration`): `RemoteTerminal::open_with(connect, RemoteTerminalOptions { reconnect, shell_integration }, ..)` types `INJECTION` (a bash/zsh OSC 7 prompt hook, nothing written to rc files) into every shell it starts, including after a reconnect, once output pauses at what looks like a prompt; `ShellOutput` hides the output from there to the hook's ready marker (no echo, no second prompt) and finds OSC 7 reports (`CwdParser`), sent as `TerminalEvent::Cwd`. Reports are parsed with the hook off too (`REPORT_CWD`). On/off is `shellIntegration` in the `terminal` settings section (`TerminalSettings` in core, `TerminalPrefs.shellIntegration` in the UI), read when a Terminal opens.
- Port forwards: rules live on the Host (`Host.forwards: Vec<PortForward>`, `{ id, label, type, ... }` with `ForwardKind` flattened and tagged by `type`; only `local` so far, remote/dynamic are new variants). They change only through `HostStore::save_forward` / `delete_forward` (`upsert` keeps them; `duplicate_host` copies them under new ids), never through `HostDraft`. `PortForwarder` (one per app, `ForwardsState` in `commands/forwards.rs`) runs them: `start(connection, &host_id, &rule)` binds synchronously (a taken port fails at once as `ForwardError::PortInUse`) and the running rule's task holds the `Arc<Connection>`, so the Connection stays up with no Terminal open and drops when the last rule stops. State (`stopped`/`running`/`failed { reason }`) is pushed through the listener to the one `forwards_watch` channel; the UI keeps it in `forwardsStore` (`features/forwards/`). The Port forwards tab is pane kind `port-forwards` (one per Host); the status bar lists Hosts kept connected by Terminals or forwards plus the running forwards.
- Export / import (`hosts/transfer.rs`): an export file is the HostStore file plus `"format": "sshastra-hosts"` (`HostStore::export` / `export_to`), so it never holds credentials and older versions import through the same `migrate`. `HostStore::import` / `import_from` gives every Group, Host and Port forward a new id and remaps `group_id` / `jump_host` (a Jump host missing from the file is dropped); a Group with the same name under the same parent is reused, a Host whose name is taken is skipped (`ImportSummary.skipped_hosts`; references to it use the existing Host). A new Host field holding an id must be remapped there too. UI: the Host list header menu and the `hosts.import` / `hosts.export` palette actions, via native pickers (`pickOpenPath` / `pickSavePath` in `lib/ipc/system.ts`, `tauri-plugin-dialog`).
- Jump hosts: `Host.jump_host` names another Host. `HostStore::jump_chain(&id)` returns the hops (outermost first, the Host last) and `upsert` refuses loops/missing hops, so callers never re-check. Connect with `ConnectionManager::connect_through(&jumps, &host, prompter)`: every hop is its own shared Connection (known_hosts + auth through the same Prompter), the next hop tunnelled over `direct-tcpip`. A failing hop is `ConnectError::JumpHost { name, source }`; over IPC it keeps the inner `kind` and adds `details.jumpHost`.
- Files: `files::RemoteFs` is the remote file system seam (object safe; `SftpFs` implements it, fakes may too); `files::browse(&fs, path)` resolves `""`/`~`/`~/x`/`..` and lists. Mutations are small `RemoteFs` methods (`create_dir`, `rename` (never replaces), `remove_file`, `remove_dir` (empty), `set_permissions`, plus `lstat`), so transfers/edits reuse them; recursive delete is `files::remove_tree` (symlinks deleted, never followed) and its confirmation count `files::count_tree`. A File panel never connects: `ConnectionManager::live(&host_id)` gives the Host's existing Connection (`files_open` fails with `notConnected` otherwise) and `Connection::open_sftp()` opens one `sftp` channel on it, which keeps the Connection alive until closed (`files_close`). Errors are `FsError` (`notFound`, `permissionDenied`, `notADirectory`, `alreadyExists` carry `details.path`; `SftpFs` turns OpenSSH's bare "failure" on mkdir/rename into `AlreadyExists` when the target exists). `RemoteFs::read_file` / `write_file` move a whole file (`write_file` truncates; small files only).
- Remote editing (`edit::RemoteEditor`, one per app): `open(fs, &host_id, path, on_event)` downloads to `<root>/<host id>/<edit id>/<name>`, opens it through the injected `edit::Opener` (app: `SystemOpener`, the opener plugin's `open_path`; tests record), watches the directory with `notify` (editors save by rename), debounces (500 ms, `with_debounce`) and uploads when the bytes changed, reporting `EditEvent` (`uploading`/`uploaded`/`uploadFailed { reason }`) to the `edit_open` channel. Opening an already open path re-opens it and returns the same `EditId`. `retry(id)` uploads now; `close(id)` deletes the temp dir; `close_all()` runs on `RunEvent::Exit` and deletes the root (`$TMPDIR/sshastra-edit-<pid>`). The app gives edits a `LiveHostFs` (fresh SFTP session per request on `ConnectionManager::live`), so a save after a reconnect uploads over the new Connection.
- SSH auth (`ssh/auth.rs`) tries, as far as the server's remaining methods allow: ssh-agent, the Host's key file (`HostAuth::Key { identityFile }`), password, keyboard-interactive; "partial success" moves on to the next. If all fail, the `ConnectError` names the last failure (`KeyRejected`, `KeyPassphraseIncorrect`, `KeyUnreadable`, `AgentKeysRejected`, `NoSupportedMethod`, `AuthenticationFailed`). `ConnectionManager::new` uses no agent; the app adds `.with_agent(Agent::System)` (Unix `$SSH_AUTH_SOCK`; Windows OpenSSH agent pipe, else Pageant). New `Prompter` methods get a default impl that answers `None` (cancel).

## Integration tests (Docker OpenSSH)

- `src-tauri/crates/sshastra-core/tests/sshd/`: Debian OpenSSH image (user `tester` / `testpass`, fixed test-only host key) and `docker-compose.yml`: `ssh` (published on a random loopback port), `jump` (published + private network), `internal` (private network only, reach it via `jump` as `internal:22`), `jump2` (private + deep network, via `jump` as `jump2:22`), `deep` (deep network only, via `jump` → `jump2` as `deep:22`), `counted` (published; only `tests/connection_lifecycle.rs` connects to it, so it can count server-side TCP connections with `Sshd::established_connections()`; tests using it hold a shared lock), `flaky` (published; only `tests/reconnect.rs` uses it, killing its connections with `Sshd::drop_connections()` and freezing it with `Sshd::pause()`/`unpause()`), `echo` (public network only, a socat TCP echo server; Port forward tests target `support::ECHO` = `echo:7777` through an sshd). `keyonly` (public keys only) and `kbdint` (keyboard-interactive via PAM, alone or after a key) are the same image with `sshd -o` overrides. Each container's hostname is its service name. Besides `tester` (bash), the image has `support::ZSH_USER` (`zester`, same password, login shell zsh). `tests/shell_integration.rs` renders Terminal output with the `vt100` crate to check what the screen shows. The image has a fixed root-owned tree under `/srv/files` for SFTP tests (`docs/`, `locked/` (0700), `many/` (10,000 files), `hello.txt`, `.hidden`, symlinks `docs-link` and `dangling`); tests that write make their own scratch directory under `/home/tester` (see `tests/sftp_file_ops.rs`, `Sshd::run_as_tester(script)` to set up files) and never mutate `/srv/files`. Key fixtures live in `tests/sshd/keys/` (`support::key(name)`; all but `*_unauthorized` are in tester's `authorized_keys`; `id_ed25519_passphrase` uses `support::KEY_PASSPHRASE`). Agent tests start their own `ssh-agent` and pass `Agent::Socket`, never the user's agent. Add new servers/services here, not from individual tests.
- In a test: `mod support;` then `let Some(sshd) = support::sshd(Service::Ssh) else { return };` (see `tests/ssh_connection.rs`). The harness runs `docker compose up --build --wait` once per test binary and leaves containers running. Each checkout/worktree gets its own Compose project and image tag, `$SSHASTRA_IT_PROJECT` or else `sshastra-it-<hash of the checkout path>` (`support::project()`), so parallel worktrees don't clobber each other; find them with `docker compose ls` and stop one with `docker compose -p <project> down`. CI sets `SSHASTRA_IT_PROJECT=sshastra-it-ci`.
- `SSHASTRA_DOCKER_TESTS`: unset/`auto` runs them when Docker works and skips otherwise; `require` fails instead of skipping (CI Linux); `skip` never touches Docker (CI macOS/Windows).
