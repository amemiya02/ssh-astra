# ssh-astra

The app is shown to users as **SSH Astra**: window title, `productName`, the HTML title and every UI string (`app.name` in the locales). Code identifiers keep the lowercase id `sshastra`: crates, the executable (`mainBinaryName`), the bundle identifier `dev.sshastra.app`, the keychain service, temp folders, storage keys and export file names. Renaming them would orphan users' saved data.

The app icon is a three-star constellation forming `>` followed by an underscore, giving `>_` ("Astra" means stars). Its 1024 px master is `src-tauri/icons/icon-source.png`. To regenerate every icon from it, run `pnpm tauri icon src-tauri/icons/icon-source.png -o <tmp>` and copy back only the files already in `src-tauri/icons/`; this is a desktop-only app, so leave out the android/ios output.

## Project layout

- `src/` — front end (pnpm + Vite + React + TS + Tailwind v4 + shadcn/ui). `@/` aliases `src/`.
  - `src/features/<domain>/` — UI per domain (e.g. `terminal/`).
  - `src/lib/ipc/<domain>.ts` — the only place that calls `invoke`/`Channel`; typed wrappers over Tauri commands.
  - `src/i18n/locales/{en,zh}.json` — all UI copy. Keys must match exactly (enforced by `src/i18n/locales.test.ts`).
  - `src/components/ui/` — shadcn components (`pnpm dlx shadcn@latest add <name>`).
  - UI follows `DESIGN.md`. `src/App.tsx` fills the `AppShell` slots (sidebar, tabs, workspace, filePanel, status); the Host list lives in `HostsSidebar` (`features/hosts/HostsPanel.tsx`). A tab holds one or more panes split in one orientation (`features/workspace/tabs.ts`, a pure reducer); a new pane kind extends the `PaneKind` union plus a case in `PaneContent` (`TabPanels.tsx`), and stays mounted while hidden or when neighbours split/close. A remote Terminal pane reports its Connection status (`connecting`/`connected`/`disconnected`) up to the tab dot and status bar. Window-wide shortcuts are a table in `features/workspace/shortcuts.ts` (macOS uses Cmd; elsewhere Ctrl+Shift, never plain Ctrl+letter, which the shell owns; a binding marked `appOnly` matches only when focus is outside a Terminal). Every shortcut and the platform check (`currentPlatform`) live there, including Settings (`openSettings`) and the ones a focused Terminal handles itself (`matchTerminalShortcut`, e.g. find); don't add another `keydown` listener or platform helper. The ⌘K command palette is `features/palette/`: a feature offers an action while mounted with `usePaletteActions(useMemo(() => [{ id, title, keywords?, shortcut?, run }], deps))`; register only actions that work. Ranking is `rankPalette` (`palette-search.ts`); recently opened Hosts are the `recentHosts` section. Semantic token classes only (literal hex only in `src/theme/terminal-themes.ts`); icon-only controls are `IconButton` with a `label`.
  - Settings and UI prefs go only through `src/lib/storage.ts`, backed by the versioned settings file (core `settings`). A feature declares its section next to its code with `defineSection(key, defaults, parse)` (`parse` repairs any stored value) and uses `useSetting` / `getSetting` / `setSetting`; changes apply at once and save in the background. To show a setting on the Settings tab (`features/settings/`), add a component of `SettingRow`s to `settingsPageSections` in `features/settings/sections.tsx`; list only settings that work. Core code reads a section with `SettingsStore::section::<T>()` (`#[serde(default)]` struct). Renaming a section or field needs a migration step in `settings.rs`. Window size/position are kept by `tauri-plugin-window-state`.
  - Terminals: every xterm is an `XtermView` (`features/terminal/XtermView.tsx`), which owns font/colours, search (Cmd+F / Ctrl+Shift+F, from `matchTerminalShortcut`), links, copy on select, right-click paste and the multi-line paste confirmation (`planPaste`, off when `confirmMultilinePaste` is); a backend wires in through its `attach(xterm)` callback. Terminal preferences are the `terminal` settings section (`terminalSetting` in `features/terminal/terminal-prefs.ts`, `TerminalPrefs` repaired by `normalizeTerminalPrefs`), read and changed with `useTerminalPrefs()` and edited on the Settings tab (`features/settings/terminal-section.tsx`). Colour schemes are in `src/theme/terminal-themes.ts` (`terminalSchemes`, `resolveTerminalTheme`); a Host may set its own (`Host.terminalScheme`, opaque to the core). Clipboard and opening URLs go through `src/lib/ipc/system.ts` (Tauri clipboard-manager / opener plugins).
  - File panel (`features/files/`): one per remote Terminal pane, kept in `fileBrowsers` (`fileBrowsers.ts`, by pane id; `find(paneId)` to drive one, e.g. follow the Terminal's `cd`). Each is a vanilla Zustand store from `createFileBrowserStore(api, hostId)` (fake `FilesApi` in tests): `connect()` / `disconnect()`, `navigate(path)` (absolute, `~`, `~/x`), `up`, `refresh`, `open(entry)`, and `selection` (entry names in `path`, changed by `select(name, "only" | "toggle" | "range", displayedNames)`) for file operations and transfers to act on. File operations are store actions on entry names in `path` (`createFolder`, `rename`, `countForDelete`, `remove`, `setPermissions`): each refreshes and resolves with the `CommandError` (or `null`) for its dialog (`FileOperationDialogs.tsx`, opened from the context menu, the New folder button, F2 and Delete / Cmd+Backspace), never touching the listing's `error`; `operationErrorText` (`fileErrors.ts`) words their failures. Sorting/hidden-file filtering is the view's (`shownEntries` in `fileList.ts`, prefs in the `files` settings section). `followConnection(store, status, shown)` opens SFTP only once its pane is `connected` and the dock is shown (`useFilePanelDock().collapsed`), and closes it while the Connection is down, so a reconnect reopens it on the new Connection at the same path. Rows are virtualized at a fixed height (`visibleRows`). `open(entry)` on a file (or a link to one) starts a remote edit, unless it is over `maxEditSize` (10 MB) or the core says `binary`: then `editQuestion` is set and `EditQuestionDialog` offers Download (or, for binary, Open anyway via `answerEditQuestion("open")`). `edits` lists them per File panel (`RemoteEditItem`: `opening` → `editing` → `uploading`/`uploaded`/`uploadFailed`, or `openFailed`), with `retryEdit(path)` / `closeEdit(path)`, shown by `RemoteEdits` in the panel footer. Edits survive `disconnect()` (a Connection drop); `dispose()` (the pane closed, via `fileBrowsers.retain`) closes them. The panel follows its Terminal's `cd` through `terminalCwds` (`terminalCwds.ts`): `RemoteTerminalView`'s `onCwd`/`onTerminal` feed it (wired in `TabPanels`), it navigates the pane's store when the reported directory changes, and `sync(paneId)` (the header button) goes back there, typing `terminal_report_cwd` into shells that don't report by themselves.
- `src-tauri/` — Cargo workspace root and the Tauri app crate (`sshastra`, lib `sshastra_lib`): a thin IPC bridge.
  - `src-tauri/src/commands/<domain>.rs` — Tauri commands, registered in `src-tauri/src/lib.rs`. Errors map to `CommandError { kind, message }` in `src-tauri/src/error.rs`.
  - `src-tauri/crates/sshastra-core/` — all domain logic, no Tauri dependency (CI checks this). Tests in `crates/sshastra-core/tests/`.
- Streams (terminal output, later transfer progress / Connection state) go to the UI through a `tauri::ipc::Channel` passed as a command argument, never polled. Terminals use one channel each: raw bytes for output, JSON `{ connection }` when a remote Terminal's Connection drops / reconnects, JSON `{ cwd }` when its shell reports its directory, then a JSON `{ exitCode }` message last.
- Host list state lives in the Zustand `hostsStore` (`features/hosts/hostsStore.ts`, built by `createHostsStore(api)` so tests inject a fake API). Every change goes through the HostStore first and is shown once saved; tree commands (`host_move`, `group_move`, `group_delete`) return the whole `HostTree`. Pure tree logic (nesting, fuzzy search, drop → move) is in `features/hosts/hostTree.ts`.
- In-app drag and drop uses `@dnd-kit/core` (pointer events), not HTML5 drag and drop, which Tauri's native file drop (`dragDropEnabled`) intercepts on Windows.
- Credentials (`credentials`): the `CredentialVault` trait keeps passwords and key passphrases under "Host id + `CredentialKind`" (keychain service `sshastra`, account `<host id>:password` / `<host id>:key-passphrase`). `credentials::system_vault()` is the OS keychain via `keyring`, or `NoVault` (`can_save() == false`) where there is none, e.g. Linux without a Secret Service. `ConnectionManager::with_vault` makes auth try the saved secret before prompting, forget it when rejected, and save a typed one whose `Secret.save` is set once it proves right; vault failures never fail a connect. `PasswordPrompt`/`PassphrasePrompt.can_save` drives the "save" checkbox; `Prompter::password`/`passphrase` return `Option<Secret>`. Tests use `MemoryVault`, never the real keychain. No credential is ever written to sshastra's own files (`tests/credential_vault.rs` checks).
- Core modules: `credentials` (CredentialVault), `edit` (RemoteEditor), `forward` (Port forward rules, PortForwarder, the SOCKS5 server for dynamic forwards), `hosts` (HostStore: versioned JSON (v2 adds Groups; Hosts carry `group_id`; siblings ordered by list position; v3 adds `Host.forwards`; v4 adds `PortForward.autoStart`; v5 adds `Host.defaultDirectory`, where a File panel opens first (`createFileBrowserStore(api, hostId, startPath)`, home if blank or gone; ssh_config import leaves it empty)), atomic writes, no secrets; a format change bumps the version with a step in `migrate`, which also reads export files), `settings` (SettingsStore: versioned JSON of opaque sections, migrations), `known_hosts` (OpenSSH `known_hosts`, shared with the `ssh` CLI), `ssh` (ConnectionManager / Connection / RemoteShell / HeldConnections), `ssh_config` (SshConfigImporter, below), `files` (RemoteFs / SftpFs / FsRegistry, LocalFs / DiskFs, TransferQueue), `terminal` (Terminal trait, LocalPty, TerminalRegistry, ShellIntegration).
- `~/.ssh/config` import (`ssh_config`): `parse(text, &ParseContext, includes)` is pure (no file access; `Include` patterns go through the `includes` resolver, `FsIncludes` / `parse_user_config` on disk) and returns `ConfigHost`s (Jump hosts by name; `ProxyJump` hops that aren't aliases become Hosts of their own, named as written) plus `ImportIssue { entry, dropped, problem }`. `HostStore::import_ssh_config` saves them in one write, skipping taken names (and linking Jump hosts to them), returning `ImportReport { imported, skipped, issues }`; command `hosts_import_ssh_config`, palette action `hosts.importSshConfig`, Host list header menu (shared with export / import, below), empty-state button. `LocalForward` / `RemoteForward` / `DynamicForward` become local / remote / dynamic rules with `autoStart` on (ssh sets them up on every connect). New `ImportProblem` kinds need `hosts.import.problems.<kind>` copy.
- SSH: get a Connection with `ConnectionManager::connect(&host, prompter)`; it is shared per Host and lives while any holder keeps its `Arc` (a RemoteShell holds one); dropping the last one disconnects. Concurrent connects to the same Host (or the same Jump host) coalesce on a per-Host slot (the later ones wait and share the result; if the first fails they try themselves). Anything needing the user mid-connect (host key, password, later passphrase / keyboard-interactive) is a method on the `ssh::Prompter` trait; the app implements it in `src-tauri/src/prompts.rs` as a prompt `Channel` plus the `prompt_answer` command. Host key Mismatch/Revoked is never a prompt: it fails with a `ConnectError`. Timeouts: TCP connect and a Jump host's `direct-tcpip` 15 s; each hop's SSH handshake + authentication 20 s of waiting on the server (`with_handshake_timeout`; `ssh::handshake` pauses the clock while a `Prompter` question or a vault call is open), failing as `ConnectError::TimedOut`; with keepalives on, `inactivity_timeout` is five keepalive intervals.
- Dropped Connections: Connections send keepalives (the `connection` settings section, `keepaliveSeconds`, default 30, 0 = off; `ConnectionSettings` in core, `connectionSetting` in `features/connect/connection-settings.ts`), applied by `ConnectionManager::set_keepalive_interval` to Connections opened afterwards. A remote Terminal is an `ssh::RemoteTerminal`, opened with a `connect` closure it calls again to reconnect: when its Connection drops it sends `TerminalEvent::Connection(ConnectionState::Reconnecting { attempt, attempts })`, retries with doubling delays (`ReconnectPolicy`, 3 tries from 1 s; refusals such as auth failures or a cancelled prompt stop early), then `Connected` with a new shell in the same Terminal, or `Disconnected { reason }` and waits for `Terminal::reconnect` (`terminal_reconnect`). The UI covers the Terminal with `DisconnectedOverlay` meanwhile. `Connection::open_shell` alone does not reconnect.
- ShellIntegration (`terminal::shell_integration`): `RemoteTerminal::open_with(connect, RemoteTerminalOptions { reconnect, shell_integration }, ..)` types `INJECTION` (a bash/zsh OSC 7 prompt hook, nothing written to rc files) into every shell it starts, including after a reconnect, once output pauses at what looks like a prompt; `ShellOutput` hides the output from there to the hook's ready marker (no echo, no second prompt) and finds OSC 7 reports (`CwdParser`), sent as `TerminalEvent::Cwd`. Reports are parsed with the hook off too (`REPORT_CWD`). On/off is `shellIntegration` in the `terminal` settings section (`TerminalSettings` in core, `TerminalPrefs.shellIntegration` in the UI): the core reads it when a Terminal opens (turning it on is not typed into shells already open, which may be mid-command), and `terminalCwds` checks it on every report, so turning it off stops open panels following at once.
- Port forwards: rules live on the Host (`Host.forwards: Vec<PortForward>`, `{ id, label, autoStart, type, ... }` with `ForwardKind` flattened and tagged by `type`: `local` (`bindAddress`, `bindPort`, `remoteHost`, `remotePort`; `ssh -L`), `remote` (`bindAddress` on the server, default `localhost`, `bindPort`, `localHost`, `localPort`; `ssh -R`), `dynamic` (`bindAddress`, `bindPort`; SOCKS5, `ssh -D`). This JSON shape is shared by the hosts file, IPC and import/export (`~/.ssh/config`, Host list), and documented on `ForwardKind`; keep it stable. They change only through `HostStore::save_forward` / `delete_forward` (`ForwardDraft` fills blank bind addresses; `upsert` keeps rules; `duplicate_host` copies them under new ids), never through `HostDraft`. `PortForwarder` (one per app, `ForwardsState` in `commands/forwards.rs`) runs them: `start(connection, &host_id, &rule).await` opens the listening end before returning (a taken local port fails as `ForwardError::PortInUse`, a remote port the server refuses as `RemoteRefused`) and the running rule's task holds the `Arc<Connection>`, so the Connection stays up with no Terminal open and drops when the last rule stops. Remote forwards ride on `Connection::listen_remote` (`tcpip-forward`; the client Handler routes `forwarded-tcpip` channels by port; dropping the listener cancels it on the server). `start_auto(connection, &host)` starts the rules with `autoStart`; every app connect goes through `commands::connections::connect_host`, which calls it. State (`stopped`/`running`/`failed { reason }`) is pushed through the listener to the one `forwards_watch` channel; the UI keeps it in `forwardsStore` (`features/forwards/`). What differs per kind (default bind address, target, status copy) is the descriptor map in `features/forwards/kinds.ts` (`forwardKind(type)`); don't switch on `rule.type` elsewhere. The status bar words a running rule with `forwardStatusText`. The Port forwards tab is pane kind `port-forwards` (one per Host); the status bar lists Hosts kept connected by Terminals, Connect only or forwards, Hosts whose Terminals are reconnecting with the try count (`reconnectingHosts`, from `Pane.reconnecting`), plus the running forwards.
- Connect only: `ssh::HeldConnections` keeps one Connection per Host open with nothing on it until released or until it drops (then it is reported and let go, not reconnected). The app's `ConnectionsState` (`commands/connections.rs`: `host_connect` (connect + auto-start forwards + hold), `host_disconnect` (stop the Host's forwards + release), `connections_watch`) pushes `{ hostId, held }` to one channel; the UI keeps it in `connectionsStore` (`features/connect/`), offered from the Host row menu.
- Export / import (`hosts/transfer.rs`): an export file is the HostStore file plus `"format": "sshastra-hosts"` (`HostStore::export` / `export_to`), so it never holds credentials and older versions import through the same `migrate`. `HostStore::import` / `import_from` gives every Group, Host and Port forward a new id and remaps `group_id` / `jump_host` (a Jump host missing from the file is dropped); a Group with the same name under the same parent is reused, a Host whose name is taken is skipped (`ImportSummary.skipped_hosts`; references to it use the existing Host). A new Host field holding an id must be remapped there too. UI: the Host list header menu and the `hosts.import` / `hosts.export` palette actions, via native pickers (`pickOpenPath` / `pickSavePath` in `lib/ipc/system.ts`, `tauri-plugin-dialog`).
- Jump hosts: `Host.jump_host` names another Host. `HostStore::jump_chain(&id)` returns the hops (outermost first, the Host last) and `upsert` refuses loops/missing hops, so callers never re-check. Connect with `ConnectionManager::connect_through(&jumps, &host, prompter)`: every hop is its own shared Connection (known_hosts + auth through the same Prompter), the next hop tunnelled over `direct-tcpip`. A failing hop is `ConnectError::JumpHost { name, source }`; over IPC it keeps the inner `kind` and adds `details.jumpHost`.
- Files: `files::RemoteFs` is the remote file system seam (object safe; `SftpFs` implements it, fakes may too); `files::browse(&fs, path)` resolves `""`/`~`/`~/x`/`..` and lists. Mutations are small `RemoteFs` methods (`create_dir`, `rename` (never replaces), `remove_file`, `remove_dir` (empty), `set_permissions`, plus `lstat`), so transfers/edits reuse them; recursive delete is `files::remove_tree` (symlinks deleted, never followed) and its confirmation count `files::count_tree`. Nothing on the File panel side connects; SFTP over a Host's existing Connection comes only from `ConnectionManager` (`notConnected` if there is none): `open_sftp(&host_id)` opens a session of its own (a File panel's, via `files_open`; it keeps the Connection alive until closed with `files_close`), and `live_sftp(&host_id)` hands out the Host's shared session (transfers and remote edits, through `commands::files::live_sftp`), reopened after a reconnect. Errors are `FsError` (`notFound`, `permissionDenied`, `notADirectory`, `alreadyExists` carry `details.path`; `SftpFs` turns OpenSSH's bare "failure" on mkdir/rename into `AlreadyExists` when the target exists). Contents stream through `open_read` / `create_write` (finish a writer with `shutdown()`); `read_file` / `write_file` are provided methods over them that move a whole file in memory (`write_file` truncates; small files only, e.g. remote editing).
- Remote editing (`edit::RemoteEditor`, one per app): `open(fs, &host_id, path, on_event)` (only regular files up to `MAX_EDIT_SIZE`, else `NotAFile` / `FsError::TooLarge`; NUL bytes in the first 8 KB fail as `Binary` unless opened with `open_binary`; `RemoteFs::read_file` itself refuses more than `READ_FILE_LIMIT`) downloads to `<root>/<host id>/<edit id>/<name>`, opens it through the injected `edit::Opener` (app: `SystemOpener`, the opener plugin's `open_path`; tests record), watches the directory with `notify` (editors save by rename), debounces (500 ms, `with_debounce`) and uploads when the bytes changed, reporting `EditEvent` (`uploading`/`uploaded`/`uploadFailed { reason }`) to the `edit_open` channel. Opening an already open path re-opens it and returns the same `EditId`. `retry(id)` uploads now; `close(id)` deletes the temp dir; `close_all()` runs on `RunEvent::Exit` and deletes the root. The app uses `RemoteEditor::start($TMPDIR/sshastra-edit)`: a per-run folder marked live by a locked `.lock` file; on startup it deletes run folders whose lock nobody holds (a crashed run). The app gives edits a `files::LiveHostFs` (asks `live_sftp` for the session on every request), so a save after a reconnect uploads over the new Connection.
- Transfers: `files::TransferQueue` (one per app, `TransfersState` in `commands/transfers.rs`) uploads/downloads files and folders (recursively; a folder's files copy one after another, symlinks to folders are not followed) between a `files::LocalFs` (`DiskFs`; the local seam) and a `RemoteFs`, using `open_read` / `create_write` / `create_dir` on both sides. At most `TransferSettings.concurrency` transfers run (the `transfers` settings section, default 3; `settings_set` applies it at once). An existing destination file pauses the transfer in `TransferState::Conflict { path }` until `answer` (overwrite/skip, or `…All`, which holds until the queue is idle); `cancel` keeps the files already copied (a cancelled or failed transfer deletes the file it was partway through, via `remove_file`), `retry` skips files already done. Each change goes to the listener as a whole `Transfer` (progress throttled to every 100 ms) and on to the one `transfers_watch` channel; the UI keeps them in `transfersStore` (`features/transfers/`, which measures speed), shows `TransfersPanel` inside the File panel (whose listing refreshes when an upload into the folder shown finishes, `followUploads`), `ConflictDialog` app-wide, and a status bar summary. Transfers run on the Host's shared `live_sftp` session (`files_open`'s session stays for browsing). Unit tests use the in-memory `MemoryFs` in `tests/transfer_queue.rs`. Files dropped from the OS file manager arrive through Tauri's drag-drop events (`onOsFileDrag` in `lib/ipc/transfers.ts`, `useOsFileDrop`); local folder/file pickers are `tauri-plugin-dialog`.
- SSH auth (`ssh/auth.rs`) tries, as far as the server's remaining methods allow: ssh-agent, the Host's key file (`HostAuth::Key { identityFile }`), password, keyboard-interactive; "partial success" moves on to the next. If all fail, the `ConnectError` names the last failure (`KeyRejected`, `KeyPassphraseIncorrect`, `KeyUnreadable`, `AgentKeysRejected`, `NoSupportedMethod`, `AuthenticationFailed`). `ConnectionManager::new` uses no agent; the app adds `.with_agent(Agent::System)` (Unix `$SSH_AUTH_SOCK`; Windows OpenSSH agent pipe, else Pageant). New `Prompter` methods get a default impl that answers `None` (cancel).

## E2E smoke test

- `e2e/` (WebdriverIO + `@wdio/tauri-service`, `driverProvider: "embedded"`): `specs/smoke.e2e.ts` adds a Host for the Docker `ssh` service (same Compose project as the Rust tests, `e2e/support/sshd.ts`), connects, trusts the host key, runs a command, `cd`s (File panel follows) and uploads a file, checked on the server with `docker compose exec`. Runs on macOS and Linux (CI job `e2e`, under `xvfb-run`, three times in a row; `e2e/artifacts/` (screenshots, page source, logs) is uploaded on failure).
- The app is built with the `e2e` Cargo feature (`pnpm e2e:build`): it embeds the WebDriver server (`tauri-plugin-wdio-webdriver`) and uses `NoVault` instead of the keychain; `lib.rs` refuses the feature in a release build. `VITE_E2E=1` adds the front-end hooks in `src/lib/e2e.ts` (`window.__sshastraE2E`: answers for the upload file picker, Terminal text); otherwise they compile away. Add a hook only for what WebDriver cannot reach (native dialogs, canvas).
- The app runs with a throwaway `$HOME` (and XDG dirs) holding a settings file that pins English, and no ssh-agent (`e2e/support/sandbox.ts`), so it never touches the developer's `~/.ssh` or settings.
- README screenshots (`docs/screenshots/`): `pnpm e2e:build && pnpm screenshots` (`e2e/wdio.screenshots.conf.ts`, spec `e2e/screenshots/screenshots.e2e.ts`; not in `pnpm e2e` or CI). It starts its own demo servers (`e2e/screenshots/docker-compose.yml`: a throttled `bastion` Jump host in front of `web-01`, `api-01`, `nas.lan`), seeds a fictional Host list, key and known_hosts into the sandbox (`e2e/screenshots/demo.ts`), and takes the servers down when done. ImageMagick (`magick`) crops and shrinks the PNGs. Run it again to refresh them; look at every image afterwards.
- Driving the UI: the embedded driver's typed lower-case letters reach xterm as function keys, so the spec pastes commands (a `paste` event) and presses Enter; focus a Terminal through its `.xterm-helper-textarea`; open a Host with click + Enter (no double-click). Enter/exit animations are switched off by the spec.

## Commands

- `pnpm dev` / `pnpm tauri dev` — front end only / full app
- `pnpm lint`, `pnpm typecheck`, `pnpm test` (Vitest)
- `cd src-tauri && cargo test --workspace` (runs the Docker integration tests if Docker is available; also `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`)
- `pnpm tauri build --debug --no-bundle` — build the app
- `pnpm e2e:build && pnpm e2e` — build the E2E app and run the smoke test (needs Docker; Linux without a display: `xvfb-run pnpm e2e`)
